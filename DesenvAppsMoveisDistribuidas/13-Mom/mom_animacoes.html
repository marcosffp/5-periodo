📬 Fila Point-to-Point (P2P)

Cada mensagem é consumida por exatamente um consumidor. O broker armazena as mensagens enquanto o consumidor não está disponível. Após a leitura com ACK, a mensagem é removida da fila.

1 consumidor
Garantia

Exatamente 1×

Com ACK, cada mensagem é processada por um único consumidor. Sem ACK → reentrega.

Durabilidade

Persistência no broker

O consumidor pode estar offline. O broker retém a mensagem até que seja lida com sucesso.

Escala

Competing Consumers

Múltiplos workers competem pelas mensagens. Cada tarefa vai ao primeiro disponível.

Caso de uso

Task Queues

Processamento de pedidos, envio de e-mails, geração de relatórios, pagamentos.

📡 Publish/Subscribe — Tópicos

Uma mensagem publicada num tópico é entregue a todos os assinantes de forma independente. O produtor não conhece os consumidores — máximo desacoplamento de espaço.

3 assinantes
Modelo

Broadcast independente

Cada assinante recebe cópia do evento de forma autônoma. Adicionar assinantes não afeta os existentes.

Desacoplamento

De espaço

Publisher não conhece IPs ou endpoints dos consumidores. Zero acoplamento direto.

EDA

Event-Driven Architecture

Um evento OrderCreated aciona Stock, Email, Audit e Payment — sem que nenhum se conheça.

Tecnologias

RabbitMQ Fanout / MQTT

RabbitMQ Fanout Exchange, AWS SNS, MQTT para IoT, Redis Pub/Sub, Google Pub/Sub.

⚡ Kafka — Log de Commit Distribuído

Kafka não destrói mensagens após o consumo. Mantém um log imutável particionado. Múltiplos consumer groups leem de forma independente, cada um com seu próprio offset.

Group A · AuditService
offset: 0 / 0
Group B · AnalyticsService
offset: 0 / 0
Eventos no log (não apagados)
0 eventos
// Partição 0 — aguardando eventos…
Log imutável

Append-only

Mensagens nunca são apagadas por consumo. O log cresce sequencialmente; cada entrada tem offset único e permanente.

Consumer Groups

Offsets independentes

Group A no off=1, Group B no off=5 — cada um avança no seu ritmo, sem interferir no outro e sem apagar o log.

Reprocessamento

Time-travel

Possível reler eventos do início. Essencial para auditoria, replay após bug e onboarding de novos serviços.

Diferencial

Não é uma fila

Num MOM clássico a mensagem some após o ACK. No Kafka, ela permanece — vários groups leem o mesmo evento de forma independente.
